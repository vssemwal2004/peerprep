## Read-through version (same words, no timecodes)

**The problem.** Every placement season looks the same. Students code on one site, take mock tests on another. Interview prep happens alone, without feedback. Placement teams see none of it, from preparation to the drive. They learn who needed help too late.

**PeerPrep.** What if a student's preparation, and the college's view, lived in one place? That place is PeerPrep. Learn, practise, assess, interview, analyse. Built for students, faculty, coordinators and placement teams.

**Student dashboard.** Students resume unfinished problems. Daily missions and streaks. Coding progress and Prep Score. Then straight into coding practice.

**Prep Coding.** Prep Coding holds 4,012 problems, by topic and company. We search for Two Sum; it opens beside a code editor. Students pick a language, here C++, write their solution, then press Run. Sample cases: three of three passed. Submit goes to Judge0's sandbox. Accepted: ten hidden tests pass.

**Timed assessments.** Timed assessments, with optional proctoring. Difficulty, time and memory limits. One navigator: MCQ and coding. Next: question two.

**ANVI · AI interviewer.** ANVI, our AI interviewer. Colleges schedule it per cohort, within a time window. Students interview by voice; reports stay pending until the placement team releases them. ANVI scores each attempt and writes a report, downloadable as a PDF. Each answer gets its own score, plus pace, filler words and length. And numbered action items.

**Learning analysis.** Every student gets one analysis: readiness first. Performance by area, and readiness history. Then coding accuracy, topic by topic, and what to practise next. Plus one Prep Score and a university rank.

**Multi-campus admin.** Now the other side: one console for every campus. A new university goes live in four steps. Each campus gets only the modules it needs. Service dates, seat limits.

**AI interview builder.** Placement teams build interviews in four guided steps. Role, level and difficulty shape what ANVI asks. Then we publish it for students. We track usage per session: live minutes, tokens, and Gemini AI calls.

**Prep Analysis.** Prep Analysis shows any student group's preparation, ready to download. Top students, ranked by Prep Score. Filter by feature, time period and exactly which students count. Even the scoring formula is configurable.

**How we built it.** One codebase. React web app, Node and Express API. Every request picks its university. Each has its own MongoDB. Redis queues jobs. Judge0 sandboxes code. ANVI runs on Google Gemini. We run analytics as a separate Python service.

**Business model.** Our model is B2B: universities subscribe per campus. Pricing follows seats and modules. AI interviews run on Prep Coin credits, so usage pays for compute, capped per interview.

**Built to scale.** Adding a university means adding a database. Heavy jobs are queued, and workers scale out. No new code per campus. Already 589 students onboarded. So help comes before the drive.
